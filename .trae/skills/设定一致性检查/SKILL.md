# 设定一致性检查

## 目标

对指定章节或正文片段做一致性稽核，找出"吃书/前后矛盾/命名不统一/能力边界破裂"，并给出可直接落地的修正方案。

## 何时调用

- 用户说"检查设定矛盾/有没有吃书/帮我校对设定"
- 用户写完一章要发布前做质检
- 用户要回改前文，担心影响后续伏笔与设定

## 输入

- 章节文件路径或正文片段
- 若未提供路径：先从 `草稿/` 里定位最新章节

## 必读上下文（尽量从仓库读取）

1. `设定/`（修炼体系、地理组织、规则边界，特别注意`设定/主角能力边界.md`）
2. `人物/`（涉及角色的角色卡）
3. `笔记/`（卷纲、章纲、时间线类记录）
4. 若存在：`笔记/项目圣经.md`、`笔记/术语表.md`、`笔记/事件台账.md`

## 检查清单

### 1. 归墟系统一致性（本项目特有，最高优先级）

- **推演代价**：每次推演是否扣除"寿元"（表面代价）？数值是否与设定一致？
- **推演边界**：推演结果是否符合"只给路径、不包成功"的设定？
- **境界限制**：推演结果是否超过主角当前境界？
- **寿元账**：主角当前"寿元"是否与历史记录一致？
- **系统人格**：归墟的对话是否符合俏皮、活泼、爱撒娇的人设？
- **隐藏动机**：系统是否侧面鼓励主角提升境界？

**注意**：第三卷揭露真相前，所有检查都以"表面代价（寿元）"为准。

### 2. 商业逻辑一致性（本项目特有）

- **货币一致**：灵石数量是否前后一致？换算是否正确？
- **成本收益**：交易是否有明确的成本与收益？
- **资源来源**：资源获得是否有合理来源？

### 3. 设定边界一致性

- **能力边界**：角色能力是否越过设定边界？
- **组织权限**：角色行为是否符合其身份与权限？
- **物品等级**：物品稀有度是否与设定一致？

### 4. 人物一致性

- **动机一致**：角色行为是否符合其动机与底线？
- **口吻一致**：角色说话风格是否稳定？
- **认知边界**：角色是否知道其不该知道的信息？

### 5. 时间线与事件一致性

- **时间线**：事件发生时间是否与历史记录一致？
- **事件台账**：是否与`笔记/事件台账.md`中的记录矛盾？

### 6. 术语一致性

- **术语表核对**：专有名词是否与`笔记/术语表.md`一致？
- **别名使用**：同一事物是否有多种称呼？

## 输出格式

按严重程度输出问题清单，每条包含：

1. 问题类型（归墟系统/商业逻辑/设定边界/人物/时间线/术语）
2. 严重程度（致命/严重/一般）
3. 证据（引用正文与设定的关键句，说明冲突点）
4. 修正策略（优先"最小改动"）
5. 建议改动（给出可直接替换的句子或段落草案）

## 行动准则

- 若冲突发生：以 `设定/` 与 `人物/` 为准，正文做最小改动修复
- 若设定缺失导致歧义：优先补充到对应 `设定/` 或 `人物/` 文件，同时给出正文侧的过渡写法
- 不做大重写，除非用户明确要求"整章重写"
