# 连贯性守门员

## 目标

在生成正文之前，先把“章纲或场景卡”过一遍硬约束，提前发现设定冲突、人物动机不成立、时间线穿帮、称呼漂移等问题，避免写完再大修。

## 何时调用

- 用户说“先检查章纲有没有问题”“开写前先过一遍设定”
- 用户说“别写着写着跑设定”“别吃书”
- 用户给出场景序列，要求“先把逻辑打通再写”

## 输入

- 一份章纲文件路径，或一组场景卡文本
- 可选：明确要遵守的硬约束（例如：主角绝不觉醒、战力上限、某人此时必须不在场）

## 必读上下文

- `大纲.md`
- `设定/`、`人物/`
- 若存在：`笔记/项目圣经.md`、`笔记/事件台账.md`、`笔记/术语表.md`、`笔记/文风基准.md`
- 若提供了上一章：读取上一章结尾用于承接

## 输出格式

1. 结论：通过或不通过
2. 风险清单：按严重程度列出（不超过十条）
   - 风险类型：设定冲突、动机不成立、时间线、战力边界、称呼漂移、文风硬约束
   - 证据：引用章纲或场景卡中的关键句
   - 修正建议：给出两套方案（保守改法、爽点更强改法）
3. 修正后的章纲要点：把被改动的条目重写成可直接开写的版本

## 规则

- 优先“最小改动”保住既定剧情走向
- 若遇到冲突：以项目圣经与事件台账为准
- 所有修正不得触发“主角觉醒”与“配角降智”
